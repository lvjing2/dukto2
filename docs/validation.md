# 验证范围

[English](en/validation.md) | 简体中文

截至 2026-10-21。以下区分当前工作区检查与既有设备测试；旧包成功不代表当前源码已在所有平台复验。

## 上传无进展超时与 Android 锁屏定位（2026-10-21）

- 发送端原先只限制整笔上传最多 2 小时，文件源停滞时缺少独立无进展预算。真实回环 TLS 回归在修复前超过测试的 3 秒等待仍未退出；修复后默认连续 30 秒无非空数据被 HTTP 写入端消费时主动停止源订阅和连接，持续有进展的文件不再受固定 2 小时总时长限制。TCP 背压下仅关闭连接仍可能让 `addStream` 挂起，因此调用者还等待显式停止信号；超时后禁止进入校验或提交。
- `tool/check.sh`：150 项应用测试、71 项核心测试、22 项脚本测试及两个静态分析器通过；CI 同款格式检查 65 个文件无变动。新增真实 TLS 场景覆盖源停滞后的清理与重发、接收端不读造成的 TCP 背压、背压中的主动取消、持续慢传输超过无进展预算。Android 与 macOS Release 构建通过。
- REDMI K90 / Android 17 未接电时，Mac CLI → 官方签名 rc.8 Android 的 128 MiB + 17 字节息屏接收完成，手机实际文件长度与独立 SHA-256 一致。反向锁屏两文件批次中 1 MiB 项成功，随后 128 MiB 项在约 5 MiB 断开；同一大文件在前台重发完成，Mac 独立磁盘校验通过。
- 本轮当前核心的本地签名 rc.10+17 验证包也复现相同锁屏批次失败。仅在忽略的验证副本中把服务类型从 `dataSync` 改为 `connectedDevice` 的对照仍失败，未将这项原生修改合入工作区。系统日志记录退后台约 6 秒后 HyperOS `GreezeManager` 冻结应用 UID，前台服务仍在、CPU 锁为 `DISABLED isFrozen=true`，框架网络策略为 `effective=NONE`；已记录原选项「智能限制后台运行（推荐）」；仅将该应用改为「无限制」后，同一服务类型对照包、同一两文件批次在未接电息屏状态下全部完成，Mac 独立文件长度及 SHA-256 一致。传输中 CPU 锁有效、`isFrozen=false`，完成后服务与唤醒锁释放。恢复原 `dataSync` 验证包后，同一两文件批次息屏复验再次完成，大小与独立 SHA-256 全部匹配，前台服务和唤醒锁正常释放；这项单变量对照支持厂商应用省电限制导致本机断传。
- 官方包与本地验证包签名不同，未通过卸载替换正式包；用户随后自行卸载正式版，并在正常系统安装界面安装本地验证包。它不是对 GitHub Release 的覆盖升级验收。手机已保留数据恢复原 `dataSync` 本地验证包，并按用户要求恢复「智能限制后台运行（推荐）」，因此原策略下锁屏断传风险仍存在；测试接收器已停止。测试证据保存在本机 `artifacts/upload-stability-20261021/`。
- HyperOS 省电策略问题已记录为 [社区 Issue #2](https://github.com/lvjing2/dukto2/issues/2)，按系统正常限制行为以 `Not planned / wontfix` 关闭，不开发绕过系统省电策略的功能。
- 以上是 Mac CLI ↔ Android 真机，不是 macOS GUI ↔ Android 验收，也不是自然深度 Doze、超过 4 GiB 完整传输或应用无需系统设置即可解决锁屏断连的结论。

## 对端取消确认与设备列表精简（2026-10-21）

- 修复前，真实回环 TLS 的接收端主动取消回归返回网络故障；修复后发送端仅凭固定证书指纹的 HTTPS、当前 token 与源 IP 对应的明确确认判定对方取消。普通断网、未知/过期 token 和未声明扩展的旧 v1 接收端不作此判断。取消凭据有效期 2 分钟、最多缓存 128 个；查询不授予文件权限，也不承担上传/提交的清理工作。
- 发送源订阅与上传连接会停止，本地取消与对方取消分别显示；文件和文本面板提供全部现有语言的对方取消提示。移除在线已选设备的「已核对 · 已选择」副标题，保留选中底色、勾、读屏选中状态，以及离线、检查中和身份变化的异常说明。
- `tool/check.sh`：150 项应用测试、67 项核心测试、22 项脚本测试通过，两个静态分析器无问题。覆盖暂停的数据源、真实断网、取消凭据容量/过期、已开始提交、旧 v1 响应及实际面板提示；列表精简后完整检查再次通过。
- Mac 独立测试接收端在收到 2 MiB 后主动取消，REDMI K90（Android 17）真实发送界面显示「对方已取消传输」，Mac 未留下未完成文件。反向由手机实际取消正在接收的限速文件，Mac CLI 明确返回 `Transfer cancelled by peer`；手机临时文件与 MediaStore 待提交记录清理完成，前台传输服务退出。
- 取消后使用最终手机包重新接收 1 MiB + 17 字节的新请求，确认弹窗再次出现；实际落盘大小和独立 SHA-256 校验通过，结束后前台服务正常退出。
- 手机已保留数据覆盖更新本地 Release 验证包，Mac Release 构建通过。列表精简也已在实际手机界面确认。证据位于本机 `artifacts/peer-cancel-20261021/`；本轮为 Mac CLI ↔ Android 真机验收，不是 macOS GUI ↔ Android 或旧设备验收，未发布新的 Release。

## 慢网络在线状态回归（2026-10-21）

- 默认将广播、Bonjour、手动地址及已核对端点的 HTTPS 探测预算放宽到 2 秒；子网扫描仍最多使用 800 毫秒，避免扩大整段扫描耗时。已发现设备的心跳预算为 2 秒，最后一次成功确认后的 3 秒移除期限保持不变。
- 已选设备每秒尝试复查，并复用未完成的探测；此前在线的设备需连续失败 3 次才变灰。首次检查失败不授予在线状态，切换设备清空失败次数，设备 ID 或证书指纹变化立即阻止发送。显示上的短暂容错不代替发送前复查：复查失败不会创建传输，并立即显示离线。
- 修复前，单次失败保留在线状态、1.2 秒的所选设备响应，以及真实回环 TLS 的 1.1 秒首次广播/心跳响应回归均失败；修复后 `tool/check.sh` 的 147 项应用测试、63 项核心测试和 22 项脚本测试通过，两个静态分析器无问题。核心测试同时保留真实断开、挂起端点、伪造广播、旧探测结果及恢复的检查。
- 同源码 Android 本地 Release 验证包已由 rc.5 覆盖更新至 rc.8+15，签名与原本机开发包一致，历史记录保留；该签名不代表官方 Release 签名。macOS Release 构建通过。
- REDMI K90（Android 17）通过真实界面连接独立 Mac CLI 测试端，核对身份后在两个可路由子网间完成 128 MiB + 17 字节双向传输；两端实际落盘大小及独立 SHA-256 全部一致。两个方向均覆盖按 Home 切后台，并观察到前台传输服务持续运行。Mac CLI 主动发送，Android 使用系统文件选择器及实际发送按钮反向发送。
- 只暂停独立测试接收进程后，手机禁用发送；恢复同进程后无须重新选择即可恢复发送，测试文本在接收端逐字一致。接收端主动取消另一笔限速测试时，观察到约 28 MiB 的 MediaStore 临时文件；取消后文件及待提交记录均已删除。随后新的 1 MiB + 17 字节请求仍需单独同意，传输和独立校验通过，结束后前台传输服务退出。
- 当时发现接收端主动取消在发送端仍归类为网络失败；现已在上方「对端取消确认」一轮修复与复验。该轮原始证据保存在本机 `artifacts/connection-stability-20261021/`；动态进度期间控件导出曾无法进入空闲态，该快照不作状态依据，传输结论以实际界面截图、接收记录和文件校验为准。
- 本轮属于 Mac CLI ↔ Android 真机验收，不是 macOS GUI ↔ Android 验收；没有完成 4 GiB 端到端、息屏/深度休眠或旧 Android 设备验证。无线 ADB 仅用于调试，文件经实际局域网 TLS 传输，没有使用 ADB 端口转发。

## 核心与 CI

纯 Dart 核心曾在同机 TLS 测试中完成实际流式落盘 4 GiB + 17 字节，以及真实源文件 1 GiB + 17 字节，独立磁盘摘要一致。这些不是 Flutter GUI 内存或局域网吞吐指标。

原生 Release CI 已完成五个平台的构建与打包；CI 产物的签名和用途见 [Release CI](release-ci.md)，不能将编译通过视为真机权限和互传已通过。公开介绍截图见 [截图说明](screenshots/README.md)。

## 复验方法

运行 `./tool/check.sh` 检查共享实现。跨设备测试使用实际屏幕二维码校验完整身份，或手动核对接收端身份码，通过界面明确选择和确认，独立读取落盘文件的长度及 SHA-256。大文件或后台修改还需覆盖取消、断网、进程终止、资源释放和从头重发；报告系统、架构和实际受测版本。
