# 批量文件与传输时间

0.1.4 起采用整批确认。0.1.3 的队列逐文件弹窗已被替换。

## 操作行为

系统文件选择器一次多选；保留顺序、显示数量、总大小与文件清单。发送前可逐项移除或重新选择，取消选择器保留原清单。读取大小失败时不会提交不完整的新清单。

发送使用 v1 的 `batch` 扩展，保持 TLS 指纹固定、流式传输和逐文件完成校验。接收弹窗展示整批数量、总大小和文件清单，点击一次「接收全部」；后续匹配授权清单的文件按序接收。整批保持收发忙碌状态，Android 前台服务与防休眠请求覆盖整批。后台收尾与历史记录仍按文件更新。拒绝整批、取消或任一项出错会停止余下队列；成功文件保留，「继续发送」跳过成功项并对剩余清单重新请求一次确认。切换接收设备重置完成标记，不自动开始发送。

授权绑定实际来源地址、随机 token 及清单中的顺序、名称、大小和文件类型；额外项、重放、类型或大小替换均拒绝。两项之间空闲 2 分钟后失效，全部完成、取消或重启立即失效，不代表永久信任发送设备。最多一次选择 1000 份普通文件，仍不支持文件夹、跨重启任务或断点续传；旧版接收方会提示更新。

接收确认窗口为 5 分钟，适用于单文件、文本和批量清单；发送端留出额外 35 秒等待超时响应。该窗口与确认后的批次空闲时间分开计算。两端均需更新，旧版发送端仍可能提前停止等待。

## 时间口径

- 每条完成历史显示本机当地时间：今天 / 昨天加时分；较早日期显示月日，跨年显示年份。桌面悬停可查看完整时间。
- 新记录保存 `elapsedMs`，从开始上传 / 收流到校验提交完成，包含文件读写和校验，不包含接收确认等待。使用单调时钟，避免系统时间调整影响耗时。
- 空文件也发出开始进度事件并记录耗时；小于一秒显示「小于 1 秒」。
- 旧记录没有耗时时仅显示时间，不推测历史耗时；耗时随历史 JSON 保存和恢复。手机大字体下时间、耗时可在左侧自然换行，右侧仍只有一个操作按钮。
