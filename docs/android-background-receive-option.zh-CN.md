# Android 后台等待接收

2026-10-23 经项目负责人确认纳入主线，保持默认关闭；安装包发行另行进行。

- 设置 → 通知中手动开启，默认关闭，每次最多等待 30 分钟；重启不恢复，不随开机启动。
- 需要通知权限，以及后台等待、接收请求两个通知渠道；不满足条件时保持关闭并提示进入系统设置。
- 前台服务保留现有 Flutter 引擎和局域网监听，界面重建时复用运行时，避免创建重复服务端。
- 收到请求后显示隐私通知；点击只打开原有确认清单，必须由用户确认接收。保留原有 TLS 指纹校验、文件／批次授权、流式传输和完整性校验。
- 关闭、到期、撤销通知权限会清除通知并拒绝未确认的后台请求；已明确同意的传输可继续完成。
- 划掉应用任务时停止运行时。强制停止和厂商冻结不绕过；HyperOS 的智能后台限制仍可能使请求无法到达。
- 不添加空闲唤醒锁、自动电池豁免、云推送或自动后台重启。耗电未评估，按用户要求不再测试。

独立预览构建和检查范围见 [英文说明](android-background-receive-option.md)。以下记录区分完整应用验收与原型验证。

## 本轮检查（2026-10-23）

- 完整检查通过：23 项工具测试、165 项应用测试、71 项核心测试，以及静态分析。
- 完整应用实机通过：默认关闭、手动开启、退到桌面收到通知、点击后确认清单、确认后文件接收、界面重建、关闭后拒绝后台请求、开启后进程重启恢复关闭、拒绝通知权限时的引导、通知中的“停止等待”撤销未确认请求。
- Mac 命令行向 REDMI K90 / Android 17 发送 1,048,593 字节文件；手机原生 SHA-256 与 Mac 原文件一致。这不是 macOS 图形界面或多品牌机型验收。
- 实测发现的重复通知设置按钮已精简，并通过相关回归。
- 到期、过期通知和快速切换通过自动化验证；未实机计时等待完整 30 分钟。此前原型复现的 HyperOS 冻结限制仍存在，不保证长时间锁屏待收。
- 本轮没有调整省电策略；通知权限已恢复原授权。不测耗电。本次仅纳入源码主线，不代表已发布新安装包。
