# Dukto2 协议 v1

协议和 UI 分离。后续旧 Dukto 适配应新增独立传输实现，不在 v1 中引入无加密回退。

## 设备发现与信任

IPv4 UDP 45878，发送至 239.255.77.77 及 255.255.255.255。通过 `IP_MULTICAST_IF` 逐个 IPv4 接口发送组播，减少 VPN 默认路由影响；广播作为补充。应用每 3 秒公告一次，12 秒未见设备视为离线。JSON 公告包含 `app: dukto2`、`v: 1`、随机设备 ID、名称、实际 HTTPS 端口、证书 DER 的完整 SHA-256。单包最大 4096 字节，本机最多保留 128 个设备。监听接口或组播受限时使用手动地址。

公告和 `/v1/info` 返回的是未认证候选身份。手动 probe 比对响应里的指纹与此次 TLS 实际证书。UI 要求用户在接收设备本机界面核对 SHA-256 的前 16 个十六进制字符（64 位），确认后发送端固定完整指纹。仅在未经核对的公告中读取指纹，无法抵抗中间人攻击。

TLS 最低 1.2。每个安装在应用私有存储生成 RSA 2048 / SHA-256 自签证书和随机设备 ID。证书有效期 10 年；桌面私钥文件权限 0600，Android 使用应用私有目录。当前未接入硬件密钥库、证书轮换或持久化可信设备列表。私钥不发往网络。

接收端不认证发送端设备名称，因此每个文件都需人工同意；UI 展示实际源 IP。未知请求默认拒绝，60 秒超时，忙时返回 409。

## 文件事务

1. `GET /v1/info`：只返回协议版本和公共身份。
2. `POST /v1/offer`：`{sender, name, size}`。最大 JSON 8 KiB，最大文件 1 TiB。接收方同意后返回 192 位随机 `token`。
3. `PUT /v1/file/:token`：`Content-Length` 必须等于声明大小。接收端写独立随机目录内 `.partial`，发送与接收端各自流式计算 SHA-256。返回接收端 `{sha256, size}`。
4. 发送端比较两端摘要和长度。相同后 `POST /v1/commit/:token`，正文 `{sha256}`。接收端再次比对并将临时文件改为目标文件名，返回 `{committed: true, sha256}`。此后才算接收成功。
5. `DELETE /v1/file/:token`：取消/丢弃未提交事务。上传中取消会在读取下一个数据块或空闲超时后终止。已经提交的文件不受取消影响。

token 绑定源 IP，只能用一次，空闲 2 分钟后过期；活跃上传刷新期限。单连接读空闲 30 秒超时。取消、读写错误、摘要错误不发布最终文件。进程重启只回收符合本应用随机目录格式的空目录/临时文件，保留已完成文件。接收目录必须由应用独占，不能与另一个服务实例共用。

文件名禁止路径分隔符、空字符、控制字符、`.`/`..`、`.partial`、Windows 保留名称及尾随点/空格。目标路径只在接收端受控随机子目录中构造。未实现目录树、符号链接或远程路径写入。

## 实际限制

数据仅在本地网络直接传输，无发现服务器或云中转。身份认证依赖用户实际核对设备码。确认请求不防止局域网中的拒绝服务攻击；本实现不是经过独立安全审计的产品。接收提交和发送成功应答之间如果断网，接收方可能已有文件而发送方显示失败，重试会产生另一份文件，不覆盖原文件。
