# Dukto2 协议 v1

协议和 UI 分离。后续旧 Dukto 适配应新增独立传输实现，不在 v1 中引入无加密回退。

## 设备发现与信任

IPv4 UDP 45878，发送至 224.0.0.167 及 255.255.255.255。通过 `IP_MULTICAST_IF` 逐个 IPv4 接口发送组播，减少 VPN 默认路由影响；广播作为补充。启动按 100 / 600 / 2600 ms 重发，之后每 3 秒公告。公告是候选，必须经 HTTPS `/v1/info` 与实际证书验证才加入列表；18 秒没有确认则移除。JSON 包含 `app: dukto2`、`v: 1`、随机设备 ID、名称、实际 HTTPS 端口、完整证书 DER SHA-256。单包最大 4096 字节，最多 128 个已确认设备，探测最多 8 并发。按证书指纹去重，不将上次选择的离线目标计作附近在线设备。

公告和 `/v1/info` 可附带 `deviceType: "phone" | "tablet" | "computer"`，仅用于界面图标。缺失、未知或无效值按通用设备显示，旧版可忽略该字段；名称和类型都不代表身份或授权。iPhone / iPad 从系统 interface idiom 区分，Android 按最小屏幕宽度 600dp 区分手机 / 平板，桌面系统上报 computer。

GUI 默认 HTTPS 端口 45879；被占用时回退临时端口。无发现结果时，仅对直接连接的私有 IPv4 /24 网段做有界 HTTPS 元数据探测，保留手动地址。网络接口变化和恢复前台会重建组播订阅；闲置时用完整 HTTPS 自检监听器，失效后重新绑定。这里的确认仅证明公告与此次 TLS 证书一致，仍不替代用户核对设备码。

公告和 `/v1/info` 返回的是未认证候选身份。手动 probe 比对响应里的指纹与此次 TLS 实际证书。UI 要求用户在接收设备本机界面核对 SHA-256 的前 16 个十六进制字符（64 位），确认后发送端固定完整指纹。仅在未经核对的公告中读取指纹，无法抵抗中间人攻击。

TLS 最低 1.2。每个安装在应用私有存储生成 RSA 2048 / SHA-256 自签证书和随机设备 ID。证书有效期 10 年；桌面私钥文件权限 0600，Android 使用应用私有目录。当前未接入硬件密钥库、证书轮换或持久化可信设备列表。私钥不发往网络。

接收端不认证发送端设备名称。单个文件、文本或一份明确展示的批量清单需人工同意；源 IP 用于绑定接收事务。未确认请求在 5 分钟后拒绝，忙时返回 409。发送端等待确认响应最长 5 分 35 秒，预留接收端超时响应的网络余量；数据传输的空闲超时独立计算。

## 文件事务

1. `GET /v1/info`：只返回协议版本和公共身份。
2. `POST /v1/offer`：`{sender, name, size}`。最大 JSON 8 KiB，最大文件 1 TiB。接收方同意后返回 192 位随机 `token`。
3. `PUT /v1/file/:token`：`Content-Length` 必须等于声明大小。接收端写独立随机目录内 `.partial` 或平台提供的未提交接收目标，发送与接收端各自流式计算 SHA-256。返回接收端 `{sha256, size}`。
4. 发送端比较两端摘要和长度。相同后 `POST /v1/commit/:token`，正文 `{sha256}`。接收端再次比对并发布接收目标（普通文件 / SAF 改名，MediaStore 清除 IS_PENDING），返回 `{committed: true, sha256}`。此后才算接收成功。
5. `DELETE /v1/file/:token`：取消/丢弃未提交事务。上传中取消会关闭可取消的数据流；写入工作仍需退出或报错后才能完成目标清理。已经提交的文件不受取消影响。

token 绑定源 IP，只能用一次，空闲 2 分钟后过期；活跃上传刷新期限。单连接读空闲 30 秒超时。取消、读写错误、摘要错误不发布最终文件。进程重启回收应用独占暂存目录内的随机空目录 / 临时文件，以及 Android 私有日志记录的 pending 文档；不清理已公开文档，保留已完成文件。接收目录必须由应用独占，不能与另一个服务实例共用。

文件名禁止路径分隔符、空字符、控制字符、`.`/`..`、`.partial`、Windows 保留名称及尾随点/空格。目标路径只在接收端受控随机子目录中构造。未实现目录树、符号链接或远程路径写入。

## 批量授权（0.1.4）

`capabilities` 增加 `batch`。批量发送先经固定证书的 HTTPS `POST /v1/batch`，正文 `{token, sender, files: [{name, size}, ...]}`。客户端生成 192 位随机请求 token；清单限定 2–1000 个普通文件、总大小不超过 1 TiB、JSON 不超过 1 MiB。接收弹窗展示名称、数量、总大小及文件清单，用户确认一次后才启用本批授权。旧版缺少能力时明确提示更新，不静默回退为多次确认。

后续 `/v1/offer` 携带 `batchToken` 和从 0 开始的 `batchIndex`，服务器按实际来源地址、发送者名称、顺序、文件名、大小与类型匹配已同意清单；匹配才生成单文件 token，无须再次弹窗。每项仍执行原有上传、摘要校验和提交。提交后索引推进，已提交项不能重放；全部完成立即销毁授权。授权不包含文本、额外文件或未来会话。

`DELETE /v1/batch/:token` 可以撤回等待确认的请求或撤销剩余授权；接收方取消、任一项失败、进程退出也会撤销。批次在两项之间空闲 2 分钟失效；传输进行中不按此批次空闲时间中断文件，但单文件仍受原有超时约束。授权仅在内存中保存，恢复或重试未完成项需要重新展示剩余清单并同意。

## 实际限制

数据仅在本地网络直接传输，无发现服务器或云中转。身份认证依赖用户实际核对设备码。确认请求不防止局域网中的拒绝服务攻击；本实现不是经过独立安全审计的产品。接收提交和发送成功应答之间如果断网，接收方可能已有文件而发送方显示失败，重试会产生另一份文件，不覆盖原文件。


Android 接收目标和前台服务不改变线上协议；其状态与验收范围见 [可靠性改进](reliability.md)。

## 文本事务

`/v1/info` 及公告通过 `capabilities: ["text"]` 声明文本能力。旧版本缺省不支持；发送方不会把文本静默发送成普通文件。`POST /v1/offer` 可以附加 `kind: "text"`，缺省或 `file` 仍表示文件；未知类型被拒绝。文本上限 16 MiB（含边界），按 UTF-8 字节计数，接收前同意、上传长度和 SHA-256、提交回执均沿用文件事务。

1 MiB 以内的文本在受限内存目标中接收；更大的文本使用现有文件 / MediaStore / SAF 保存目标，逐块严格验证 UTF-8，保留最多 16384 个 UTF-16 码元的预览（避开孤立代理项）。非法编码、长度不符、摘要不符或取消均不发布。文本内容仅在成功提交后进入历史，预览与完整内容在回执中明确区分。

macOS 默认下载目录通过系统 Downloads 授权访问，自选文件夹用安全作用域书签持久授权。用户切换目录不迁移旧文件；旧目录授权为历史打开保留，恢复默认仅改变新接收目标。包标识与网络协议标识保持小写 `dukto2`，产品显示名为 Dukto2。
