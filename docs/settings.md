# 设置与通知（0.1.3）

验证日期：2026-10-18。版本：0.1.3+4。

## 当前行为

- 主界面通过齿轮进入设置，接收位置的展示和更改入口统一移入设置页。
- 接收位置默认「下载 / Dukto2」，两端均可修改并记住；自定义目录可恢复默认，不删除已有文件。macOS 使用安全书签，Android 使用 MediaStore / SAF。
- 设备名称只读，始终使用系统设置的设备名称；启动和回到前台时刷新。旧设置中的自定义名称不再生效。名称变化不更换设备身份、TLS 指纹或监听端口。
- 「传输完成通知」控制成功发送或成功接收后的系统通知。通知使用通用文案，不包含文件名或文本内容。系统未授权时可申请权限或打开系统设置；通知失败不影响已完成的传输。
- Android 的传输中前台服务通知独立保留。关闭完成通知时才展示这项说明；正常已授权状态不重复提示。
- 外观支持跟随系统、浅色和深色，设置保存在本机。保存失败时保留当前状态并提示重试。
- 设置页只保留目录、系统名称和必要的通知状态，去掉重复解释与正常状态提示。
- 最近传输左侧显示文件名、对方设备、大小、收发状态、完成时间和已保存的耗时，右侧仅保留「查看文本」或「打开目录」。文本复制统一在查看窗口内完成，大文本提供「复制预览」。

## 最近传输筛选与目录入口（2026-10-18）

- 筛选项来自本机保留的 100 条历史中的设备名称，包含离线设备；选择后再取最近 20 条，同名设备合并显示。筛选不改变发送对象，重开页面恢复「全部设备」。
- Mac 在 Finder 中选中文件；iPhone / iPad 使用系统文件浏览器打开接收文件所在目录，浏览不会更改接收位置或选定发送文件。
- Android 使用系统文件浏览器，向文件提供方传入目录提示；Android 7 / 7.1 无初始目录参数，部分文件提供方也可能忽略提示。未授权文件夹的旧版 Android 私有文件无法直接浏览目录。
- 新的 Mac 发送记录保存源文件位置；Android 保存文件选择器提供的 content URI。旧发送记录没有源位置，目录按钮禁用。iOS 选择器只返回临时副本，不能定位原目录，因此发送记录也禁用目录按钮。文件被移走或授权失效时显示错误。
- 自动检查：Flutter / 平台 31 项、Dart 核心 31 项通过，分析器无问题。覆盖离线设备筛选、先筛选再限制条数、收发状态在左侧、每行单操作，以及深色两倍字号。三端调试构建通过，日志在 `artifacts/history/`。
- 实际界面：Mac 设备筛选和 Finder 定位；iPhone 单按钮布局、接收目录定位和文本详情；iPad 离线设备筛选与接收目录定位。Mac 图形版 → iPad 模拟器发送 1,048,593 字节测试文件，独立读取 iPad 实际文件 SHA-256 与原件一致；Mac 新发送记录持久保存源 URI，点击目录按钮在 Finder 中选中原件，证据 `artifacts/history/mac-ipad.json`。Android 本次只做构建，未做真机目录浏览验收。
