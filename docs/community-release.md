## 源码与发行的边界

源码可以先按开发预览状态公开，但必须先解决上面的许可证与来源问题，不能把所有平台写成正式支持。

- Windows：旧 0.1.4+5 包已实测 Mac 文件、文本互传；后续共享代码与新图标需用新包复验，首轮三个 Windows widget 失败记录仍保留。
- Linux：Ubuntu 24.04.3 x64 编译、启动、Mac 双向文件已通过；新版已接入目录选择/记忆、“打开目录”和休眠抑制，文本互传与新增平台行为仍需桌面复验。
- Android：大文件和后台验收有历史通过证据；最新反向大批次的连接超时/中断仍未定位，见 [批量记录](batch-and-history.md)。
- iPhone / iPad：模拟器与真实 iPad 的结果分开报告，iPhone 真机和后台行为不能从模拟器推定。
- 断点续传、文件夹传输、IPv6、旧 Dukto 协议兼容和跨重启任务尚未实现。
- 没有签名的商店发行、自动更新或全系统兼容承诺。

## 建议的提交分组

1. 传输与交互：共享核心、控制器、批量授权、目录/文本/设置、历史记录和相关测试。
2. 平台接入：Android / Apple 原生改动及 Windows / Linux 工程，包含各自构建脚本与验证说明。
3. 社区资料：Apache-2.0 许可证、贡献和安全说明、致谢、截图、图标与 CI。

各组有依赖关系，不能只把 Linux runner 单独拣选到旧基线后就声称应用已完整支持 Linux。提交前检查差异，禁止将 `artifacts/`、个人签名、身份文件或真实接收内容一起加入 Git。不要为整理重写已有历史或覆盖另一任务的未提交修改。

## 检查和发布步骤

```sh
./tool/check.sh
git diff --check
git status --short
python3 tool/prepare_source.py
```

`prepare_source.py` 从 Git 已跟踪和未忽略文件生成独立源码目录、逐文件 SHA-256 清单及 `Dukto2-source-review.tar.gz`，放在 `artifacts/community/candidate-*/`。它不提交 Git、不配置远端，也不发布。清单包含未提交修改，HEAD 不能独自代表候选内容；测试与审阅应以文件摘要为准。

原生构建分别在对应主机执行，发布前核对整个 bundle 和生成的第三方通知文件。CI 必须在实际社区仓库运行后才能标记为通过。2026-10-19 的授权限于本次公开源码提交；正式 Release、安装包和应用商店发行仍需单独安排。
