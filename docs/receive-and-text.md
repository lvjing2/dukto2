# 接收位置与文本（0.1.2）

本次验证日期：2026-10-18。本文记录 0.1.2；0.1.3 已将目录入口迁入统一设置页，见 [设置与通知](settings.md)。应用显示名称统一为 **Dukto2**；包名、协议标识和安装身份保持不变。

## 行为

- macOS 默认保存至「下载 / Dukto2」，可选系统授权文件夹。安全书签在重启后恢复；保留过去的授权，以便打开历史文件。不可用的目录明确报错。
- Android 10+ 默认使用 MediaStore 保存至「下载 / Dukto2」，自定义位置使用 SAF 持久授权；恢复默认不会删除已接收的文件。
- 两端主界面展示当前位置，按钮缩短为「更改目录」「恢复默认」。是否新增完整设置页仍是后续设计议题。
- 文本支持手动输入、显式粘贴、接收确认、查看与显式复制，不自动访问剪贴板。UTF-8 上限 16 MiB，编辑区最多 1 MiB；更大文本从文件流式载入。
- 超过 1 MiB 的接收文本完整保存到接收位置，历史保留最多 16,384 个 UTF-16 码元的预览（避免截断代理对），提供复制预览和打开完整文本。
- 手机文本工具栏收为一排：粘贴、更多、发送；载入文件和清空内容放入更多菜单。操作保留至少 48dp 点击区域。键盘打开时切换为紧凑编辑布局，接收设备位于上方、工具栏固定在键盘上方；复用同一编辑器保留焦点和光标，收起键盘后恢复主页面滚动位置。
- 手动 IPv4 地址支持全角数字、冒号及句点归一化，输入和提示使用从左到右的等宽字体；端口与 IPv4 仍严格校验。

## 验证边界

大文本真机验证方向为 Mac → Android；没有把它表述为 Android → Mac 的 16 MiB 验证，也没有将核心回环速度当作 Wi-Fi 吞吐。未验证 Android 锁屏/后台长传、进程死亡恢复、旧版 Android、Intel Mac 或其他桌面系统。

验收时发现 Android 首次通知权限弹窗会阻塞传输启动回调，已改为权限申请与前台服务启动独立完成。修复已构建，最终 APK 的文本传输通过；首次拒绝通知权限的完整新装流程尚未单独复验。

自动检查覆盖 320/375 宽手机、横屏、桌面、两倍字号与深色/减少动画模式；新增键盘打开/关闭的焦点、布局边界和滚动恢复检查；真机布局需以安装后的实际观察为准。构建产物为开发调试包，尚未配置正式签名和分发。
