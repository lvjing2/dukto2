## Improvements

- Report confirmed receiver cancellation as “The other device cancelled the transfer” instead of a network failure, for both file and text transfers.
- Add optional, certificate-pinned cancellation status checks while preserving compatibility with v1 receivers that do not advertise this capability.
- Stop cancelled uploads, clean up partial files, and release transfer resources. New transfers still require explicit receiver consent.
- Improve selected-device availability checks to tolerate transient or slow identity probes while retaining identity validation before sending.
- Simplify selected-device rows by keeping the selection highlight and checkmark without redundant status text.
- Consolidate the encrypted local-network transfer description into one sentence and update all supported translations.
- Keep the nearby-device count visible during refresh, with the progress indicator and empty-list message showing search activity.

## Validation

- Local checks passed: 150 application tests, 67 core tests, 22 script tests, and both Dart analyzers. The 37 widget tests were rerun after the final UI changes.
- A physical Android device and a Mac CLI endpoint exercised cancellation in both directions, partial-file cleanup, and a new transfer after cancellation with independent size and SHA-256 verification. This does not constitute a macOS GUI-to-Android regression test of every scenario.
- Long-running transfers during deep Doze, complete transfers larger than 4 GiB, older Android devices, and ARM64 desktop hardware acceptance remain pending.

Android versionCode increases to 17 while retaining the existing application and upload signing keys. This is a release candidate. macOS builds are ad-hoc signed and not notarized; iOS builds require developer signing. Build success does not imply acceptance testing on every supported platform.

The rc.9 release build was stopped by a test-file formatting check before platform builds began; rc.10 includes the formatting correction.
