# Dukto2 0.1.6-rc.2 release and validation record

Release candidate `0.1.6-rc.2+9`, source tag `v0.1.6-rc.2`, application commit `c6ed3ca87f6a2ef0b8c35fb9e9b442b400847abe`. At the time of this validation, the repository was private and the release was a Draft / Prerelease, without a public community or store launch.

CI: [five-platform candidate builds](https://github.com/lvjing2/dukto2/actions/runs/39209879206). Package versions, source commits, architectures and signing status are recorded in `RELEASE-INFO.json` inside archives or the original CI JSON. Archives include `SHA256SUMS.txt`; Android APKs retain their original signed bytes.

## Validation results

All five native builds and draft assembly passed. CI completed 117 application tests, 49 core tests and 15 tooling tests, plus static analysis and formatting checks for 58 Dart files. All five build JSON files identify the application commit above and `0.1.6-rc.2+9`. Android versionCode is 9; application/upload certificates and APKs derived from the AAB passed identity checks.

The macOS executable contains `x86_64 arm64`; this does not establish Intel hardware coverage. GitHub upload digests for the original eight package/license/media attachments matched their `.sha256` sidecars. Release downloads were later reorganized into five platform attachments. Original materials were retained locally and in CI; repackaged files and digests are recorded separately in the [validation JSON](https://github.com/lvjing2/dukto2/blob/main/docs/releases/v0.1.6-rc.2-validation.json).

## Included in this candidate

- Direct LAN file and text transfers, explicit batch-manifest approval, remembered receiving folders, transfer times/durations and history filtering by device.
- Ten interface languages, localized native notifications, and light/dark themes.
- Nearby discovery, known-device records, manual addresses and QR connections that verify the full fingerprint.
- Application-key signing for Android APKs and a separate upload key for Play AABs, with matching package IDs and build numbers.

## Downloads and installation

| Platform | Attachment and limitations |
| --- | --- |
| Android | `*-android.apk` is a universal installer; the Play AAB remains in CI and local backups for a future upload |
| Windows x64 | Fully extract `*-windows-x64.zip` and retain DLL/data files; not commercially code-signed; requires the VC++ x64 runtime |
| Linux x64 | Fully extract `*-linux-x64.tar.gz`; built on Ubuntu 24.04; follow the included instructions to check GTK/glibc dependencies |
| macOS | `*-macos-adhoc.zip` is ad-hoc signed and not notarized; see JSON for architecture; Intel hardware was not validated |
| iPhone / iPad | `*-ios-device-unsigned.zip` is an unsigned developer device build, not a publicly installable IPA or TestFlight package |

Existing Android debug installations use a different signing key and cannot be overwritten directly. This workflow does not automatically uninstall or clear an existing application. Google Play app creation and key import were not completed; real Play/GitHub cross-channel upgrades remained unverified.

## Tested scope and limitations

See CI for analysis, unit/widget tests, formatting and native builds. Native compilation does not establish fresh GUI, LAN or background acceptance of these candidate binaries on every device. Historical hardware coverage is listed in the [validation record](https://github.com/lvjing2/dukto2/blob/main/docs/en/validation.md). Community Android screenshots came from an installed 0.1.6+7 development build, retaining test history and original resolution; provenance and digests are in the media archive.

Resumable transfers, folder transfers, original Dukto protocol compatibility and automatic updates are not implemented. Devices require direct reachability; guest networks or router isolation can block communication. Background operation is subject to OS limits. Comprehensive compatibility with Windows 10, Intel Macs, other Linux distributions or older devices is not established.

## Privacy and feedback

File transfers do not pass through a maintainer relay. LAN discovery includes necessary device metadata; settings and history are stored locally. Android QR scanning uses ML Kit, which includes Google-disclosed SDK diagnostic/usage behavior; a blanket zero-collection claim does not cover all dependencies. Privacy-policy and data-safety drafts are in the media archive; the public policy URL and final store declarations were still pending at validation time.
