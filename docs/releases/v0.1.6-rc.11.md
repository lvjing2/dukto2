## Improvements

- Add optional Android background reception, **off by default**. Enable it in Settings → Notifications for a receive window of up to 30 minutes; restarting the app leaves it off.
- Notify about incoming background requests. Tapping opens the existing file confirmation; explicit approval is still required. Stop waiting from Settings or the ongoing notification.
- Retain the Android receive runtime across Activity recreation and preserve identity checks, bounded streaming, and file integrity verification.
- Abort stalled uploads and clean up temporary resources without publishing incomplete files.
- Update project naming acknowledgements and direct-download guidance.

## Validation and limitations

- Local checks passed: 23 tooling tests, 165 application tests, 71 core tests, and both Dart analyzers. The independent Android preview built and installed successfully.
- Mac CLI → REDMI K90 / Android 17: background request notification, notification tap and explicit consent, 1 MiB + 17-byte reception with native on-device SHA-256 verification, Activity recreation, opt-out, restart, notification denial, and stopping a pending request were checked.
- HyperOS power management may still freeze the app and prevent background delivery. This release does not bypass manufacturer restrictions or guarantee long locked-screen availability. Battery testing was not performed; the full 30-minute native waiting interval was not physically timed.
- These checks are not multi-vendor Android or macOS GUI acceptance. Existing platform signing and installation limitations remain applicable.

Android versionCode increases to 18 with the existing application and upload signing keys. This is a release candidate.
