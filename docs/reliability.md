# 可靠性与传输会话

[English](en/reliability.md) | 简体中文

## 模块边界

`packages/dukto2_core` 保持纯 Dart，负责发现、身份、TLS 和传输事务。Flutter 控制器协调界面与原生平台；文件访问通过有界流和 `ReceiveTarget` 接口连接。

`TransferSession` 统一持有一次单文件或整批传输的方向、确认、进度、计时、文件计数及取消令牌。阶段覆盖等待确认、等待上传、上传、校验、收尾、取消和终态。完成、失败、取消与退出共用一次清理；清理结束前保持忙碌，避免新会话与旧资源释放交错。

原生资源启动尚未完成时先等待其结果，再执行对应停止操作。异步准备接收目标后重新检查会话和取消状态；失效目标被丢弃。批次内逐文件保存历史，余下文件继续使用同一次明确授权。

## 错误与诊断

`TransferFailure` 包含失败阶段、原因类别、方向及独立诊断编号，保留原始异常与堆栈；平台错误保留错误码。界面通过统一映射展示中文提示。清理失败单独记录，不覆盖主要失败原因。

核心接收错误流为 `Stream<TransferFailure>`，客户端传输错误使用该类型；主动取消保留 `TransferCancelled`，调用前参数校验仍可抛出校验异常。无关的非法 HTTP 请求会被记录，但不使已经授权的应用会话退出。

内存日志默认保留最近 200 条。应用支持目录下的 `diagnostics/transfers.jsonl` 使用 JSON Lines，单文件最多 512 KiB，保留一份 `.1` 轮转文件；待写队列最多 200 条。日志写入失败不影响传输。

日志不序列化传输文件名、存储路径、文本正文、原始异常消息或授权令牌；保留有限源码堆栈位置、错误类别和系统错误码。诊断编号与传输授权令牌独立。

## 发现与网络

UDP 公告和 Bonjour 仅提供候选，HTTPS 身份确认后才显示为设备。按证书指纹去重，过期移除；接口变化和恢复前台后重建发现订阅。刷新发现不会主动中止现有文件传输。

组播不可用时，有限并发探测直接连接的私有 IPv4 /24 网段，保留手动连接。它不保证跨子网、AP 隔离或 VPN 下可达。具体端口、频率和授权约束见 [协议 v1](protocol-v1.md)。

## 存储与平台资源

- 桌面写独立暂存目标，长度和摘要正确且收到提交后才发布，不覆盖旧文件。
- Android 10+ 默认使用 MediaStore pending 条目；自选目录使用 SAF。MethodChannel 每块最多 256 KiB，并等待原生工作线程完成写入。
- iOS 使用私有暂存，再协调写入所选目录并重新校验；需要额外磁盘空间，外部文件提供方可能增加等待。
- Android 前台服务、CPU 与 Wi-Fi 锁只覆盖明确开始的收发；桌面防止空闲休眠，Apple 移动端主要在前台传输。完成、失败和取消后释放资源。

断网或杀进程后需要从头重发；启动时仅清理本应用记录的未提交目标。已经提交但丢失回执时，可能出现接收端已保存、发送端未确认，不能保证撤回或恰好一次交付。
